# Алгоритм FSM фиксации веса

Актуальная FSM работает по циклу «готовность → плато → запись → разгрузка → коррекция остатка».

## Настройки

Все параметры, влияющие на автоматическую запись, находятся в `SystemSettings` и доступны на странице **Настройки → Служба**:

- `MinWeight` — минимальная масса продукции;
- `ZeroResidualMaxKg` — единый максимум остатка для первой команды ZERO;
- `TareAllowancePercent` — допустимое превышение максимума ZERO для TARE;
- `PlateauStableSamples` — число стабильных измерений плато;
- `PlateauWindowKg` — допустимый разброс плато и разгрузки;
- `UnloadStableSamples` — число измерений для подтверждения разгрузки;
- `CommandTimeoutMs` — тайм-аут одной команды ZERO/TARE.

Верхняя граница TARE вычисляется как:

```text
TareMaxKg = ZeroResidualMaxKg * (1 + TareAllowancePercent / 100)
```

Настройки применяются после перезапуска службы. Значения `HystWeight`, `SemaphoreTimeMs`, `ScaleSettings.StableThreshold` и `ScaleSettings.UnstableThreshold` читаются из старых файлов для совместимости, но новая FSM их не использует.

## Фиксация плато

FSM принимает только свежие ответы терминала с установленным признаком стабильности. Окно сбрасывается нестабильным измерением или выходом разброса за `PlateauWindowKg`.

После `PlateauStableSamples` измерений с массой не меньше `MinWeight`:

1. вычисляется медиана окна;
2. медиана округляется до `Division` терминала, с резервным шагом 0,01 кг;
3. цикл помечается записанным;
4. запись немедленно передаётся в БД;
5. FSM остаётся в `AwaitUnload`.

Ошибка БД журналируется, но автоматического повтора нет: это исключает дубль при неизвестном результате записи. Повтор той же массы разрешён после подтверждённой разгрузки и создаёт новую запись.

## Разгрузка и остаточная вода

Разгрузка подтверждается `UnloadStableSamples` стабильными измерениями в том же окне разброса. Остаток после снятия туши не вычитается из уже записанной массы.

- положительный остаток до `ZeroResidualMaxKg` включительно: одна команда ZERO;
- только при явном отказе ZERO: одна команда TARE с измеренной массой остатка;
- положительный остаток выше `ZeroResidualMaxKg` и до `TareMaxKg` включительно: одна команда TARE с измеренной массой;
- больший по модулю остаток: красная лампа до очистки и подтверждённого околонулевого результата;
- отрицательный остаток в допустимом диапазоне: TARE текущей нагрузки, затем ZERO;
- отрицательный остаток за `TareMaxKg`: красная лампа, команды не отправляются.

Тайм-аут или ошибка COM считаются потерей связи. В этом случае TARE после ZERO не отправляется. После восстановления связи FSM сохраняет признак записанного цикла и требует нормального стабильного результата, поэтому восстановление не создаёт повторную запись.

После явного отказа TARE команда не повторяется на неизменном весе. Новая попытка возможна после заметного изменения веса и возврата к околонулевому диапазону. Стабильный штатный ноль снимает красную защёлку без дополнительной команды.

## Сигналы

Соответствие кодов Arduino не менялось:

- аппаратная авария — `RedOn`;
- потеря связи — `LinkOff`;
- очистка или отказ коррекции — `RedOn` после отключения прежней индикации;
- готовность — `Idle`;
- подтверждённое и записанное плато до разгрузки — `Completed`;
- набор плато и подтверждение разгрузки — `Unstable`.

## CRC

В этом хотфиксе расчёт и проверка CRC не изменялись. Запрос массы остаётся прежним проверенным кадром, CRC входящего ответа только вычитывается из порта. Существующий метод формирования управляющих команд оставлен без изменений.

## Локальная проверка

По правилам репозитория команды не запускаются в Codex. На ПК с .NET 8 выполнить:

```powershell
dotnet test .\Scalemon.CSTests\Scalemon.CSTests.csproj -c Release
dotnet build .\Scalemon.sln -c Release
```

Перед публикацией отдельно проверить на терминале ответы ZERO/TARE, отрицательное показание после очистки ранее тарированной платформы и два последовательных одинаковых веса.
