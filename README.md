# **Система автоматического взвешивания "Scalemon"**

🧠 **Scalemon** — это служба Windows, разработанная для автоматизации процесса взвешивания на производстве. Она считывает данные с платформенных весов "Масса-К", обрабатывает их в соответствии с заданной логикой и сохраняет результаты в базу данных MS SQL Server. Параллельно система информирует оператора о своем текущем состоянии с помощью световой индикации через контроллер Arduino.

## **Архитектура**

Решение построено на базе .NET и разделено на несколько логических проектов для лучшей поддержки и расширяемости:

* **Scalemon.ServiceHost**: Основной проект, содержащий службу Windows. Отвечает за запуск, остановку и общую координацию компонентов.  
* **Scalemon.FSM**: Ядро системы. Реализует всю бизнес-логику с помощью конечного автомата (Finite State Machine) на базе библиотеки `Stateless`.  
* **Scalemon.SerialLink**: Компонент для взаимодействия с весами "Масса-К" через COM-порт. Включает в себя как низкоуровневый драйвер, так и высокоуровневый процессор, который обрабатывает цикл опроса.  
* **Scalemon.SignalBus**: Компонент для двусторонней связи с контроллером Arduino (отправка команд на светодиоды, получение сигнала о нажатии кнопки).  
* **Scalemon.SqlDataAccess**: Компонент для взаимодействия с базой данных MS SQL. Реализует отказоустойчивую логику с очередью для повторной записи данных в случае временной недоступности БД.  
* **Scalemon.Common**: Общий проект, содержащий перечисления (`Enums`) и интерфейсы, используемые во всем решении.

1. ScaleProcessor запускает асинхронный цикл с PeriodicTimer.
2. При получении ответа от весов генерируются события: WeightReceived, Unstable, ScaleAlarm, ConnectionLost.
3. IScaleStateMachine обрабатывает триггеры через конечный автомат Stateless.
4. SignalBus отсылает коды ArduinoSignalCode для управления лампами.
5. SqlDataAccess пытается сразу записать в БД и ставит в очередь при сбоях; уведомляет FSM через события DatabaseFailed/Restored.

## **Установка и настройка**

### ***Предварительные требования***

1. **Операционная система**: Windows 10/11 или Windows Server.  
2. **Среда выполнения**: .NET Desktop Runtime 6.x (или новее).  
3. **База данных**: Установленный и запущенный экземпляр MS SQL Server.

### ***Настройка базы данных***

Перед первым запуском необходимо создать базу данных и таблицу для хранения результатов.

1. Откройте SQL Server Management Studio (SSMS).  
2. Выполните следующий SQL-скрипт:

```sql  
\-- 1\. Создание базы данных (если еще не создана)

IF NOT EXISTS (SELECT \* FROM sys.databases WHERE name \= 'WeighingDB')  
BEGIN  
    CREATE DATABASE WeighingDB;  
END  
GO

USE WeighingDB;  
GO

\-- 2\. Создание таблицы для хранения взвешиваний  
IF NOT EXISTS (SELECT \* FROM sysobjects WHERE name='Weighings' and xtype='U')  
BEGIN  
    CREATE TABLE Weighings (  
        Id INT PRIMARY KEY IDENTITY(1,1),  
        Weight DECIMAL(18, 3\) NOT NULL,  
        RecordedAt DATETIME NOT NULL DEFAULT GETDATE()  
    );  
END  
GO  
```
3. Для хранения аудита изменений выполните скрипт `Scalemon.WebApp/Data/Scripts/CreateWeighingEdits.sql`. Он создаст таблицу `[dbo].[WeighingEdits]` с индексами по времени и пользователю. Таблица сохраняет снимок исходной записи (`RecordedAtSnapshot`, `OldWeight`, `NewWeight`), поэтому аудит доступен даже после удаления исходной строки.


### ***Настройка приложения***

Все параметры работы службы настраиваются в файле `appsettings.json`, который должен находиться в одной папке с исполняемым файлом службы.

```json

{  
  "DatabaseSettings": {  
    "MaxRetryQueueSize": 100,  
    "ConnectionString": "Server=.\\\\SQLEXPRESS;Database=WeighingDB;Trusted\_Connection=True;",  
    "TableName": "Weighings"  
  },  
  "ScaleSettings": {  
    "PortName": "COM2",  
    "PollingIntervalMs": 200,  
    "StableThreshold": 3,  
    "MinWeight": 5.0,  
    "HystWeight": 0.1  
  },  
  "PLCSettings": {  
    "PortName": "COM1",  
    "BaudRate": 9600  
  }  
}  
```

**Описание параметров:**

* `DatabaseSettings`:  
  * `MaxRetryQueueSize`: Максимальное количество взвешиваний, которые будут храниться в памяти при недоступности БД.  
  * `ConnectionString`: Строка подключения к вашему экземпляру MS SQL Server.  
  * `TableName`: Имя таблицы для записи результатов.  
* `ScaleSettings`:  
  * `PortName`: Имя COM-порта, к которому подключены весы.  
  * `PollingIntervalMs`: Интервал опроса весов в миллисекундах.  
  * `StableThreshold`: Количество одинаковых ответов от весов, после которого вес считается стабильным.  
  * `MinWeight`: Минимальный вес (в кг), который считается валидным для записи.  
  * `HystWeight`: Порог гистерезиса (в кг). Вес ниже этого значения считается шумом.  
* `PLCSettings`:  
  * `PortName`: Имя COM-порта, к которому подключен Arduino.  
  * `BaudRate`: Скорость передачи данных для порта Arduino.

### ***Установка службы***

1. Скомпилируйте проект и скопируйте все файлы из папки `bin/Release` в постоянное место на сервере (например, `C:\Program Files\Scalemon`).  
2. Откройте командную строку (cmd) или PowerShell **от имени администратора**.

Выполните команду для создания службы:  
```cmd  
sc create Scalemon binPath="C:\\Program Files\\Scalemon\\Scalemon.ServiceHost.exe"  
```

3. 

(Опционально) Добавьте описание для службы:  
```cmd  
sc description Scalemon "Служба для автоматической фиксации взвешиваний с весов Масса-К."  
```

4. 

Запустите службу:  
```cmd  
sc start Scalemon  
```

5. 

   Для остановки используйте `sc stop Scalemon`, для удаления — `sc delete Scalemon`.

## **Логика работы**

Основной цикл работы системы управляется конечным автоматом и выглядит следующим образом:

1. **Готовность**: На весах нет груза. Горит **зеленая** лампа.  
2. **Взвешивание**: На весы помещается груз. Зеленая лампа гаснет. Система ожидает стабилизации веса.  
3. **Фиксация**: Вес стабилизировался и превышает `MinWeight`.  
   * **Успех**: Данные записываются в БД, загорается **желтая** лампа. Система ждет, пока груз уберут.  
   * **Ошибка**: Если предыдущий груз не был убран (не было обнуления), загораются **желтая и красная** лампы.  
4. **Завершение**: Груз убран с весов. Желтая лампа гаснет. Система возвращается в состояние готовности (п.1).

При возникновении аппаратных ошибок или сбоев с базой данных загорается **красная** лампа, и система переходит в состояние ошибки, ожидая устранения проблемы.

## Журнал правок

В веб-интерфейсе добавлена страница `Журнал правок` (`/weighing-edits`). На ней отображаются записи из таблицы `WeighingEdits` и доступны фильтры по диапазону дат, пользователям и типу события. Пункт меню виден для ролей Editor и Admin.
**Логирование**

Начиная с текущей версии основная информация о работе сервиса сохраняется в базу данных SQLite. Для каждой календарной даты создаётся отдельный файл (например, `mainlogs20240214.db`) в каталоге, заданном параметром `Logging:Database:MainDatabasePath` файла `appsettings.json`. Для обратной совместимости путь к текстовому `main.log` остаётся в конфигурации и может использоваться для импорта исторических данных.

* **mainlogsYYYYMMDD.db**: Основной журнал событий с уровнем не ниже `Information`. Веб-интерфейс и REST API читают данные из соответствующих баз и агрегируют их для просмотра, сохраняя производительность даже при больших объёмах.
* **detailed.log**: Необязательный детальный текстовый лог с уровнем `Debug`, который можно оставить включённым при необходимости глубокой диагностики.

## Сверка ручного реестра и экран цеха

Страница `/weight-register-review` реализует рабочий процесс «загрузка → калибровка → распознавание → сравнение → ручная коррекция». Проекты хранятся в `WeightRegisterReview:StoragePath` как исходные изображения и JSON schema v2, совместимый с `WeightRegisterReviewApp` и навыком `weight-register-scans`. Производственная схема SQL Server при этом не изменяется.

Порядок работы:

1. Выберите дату разделки и загрузите JPG/PNG-листы кнопкой «Загрузить». Служба применит EXIF-ориентацию, повернёт альбомный скан в портрет и сохранит нормализованный PNG.
2. Для каждого листа проверьте синюю сетку. Как в WeightRegisterReviewApp, четыре относительных ползунка и кнопки `−/+` двигают границы с шагом 2 px, отдельный ползунок и кнопки меняют угол с шагом 0,1°; числовые поля оставлены для точного ввода. Затем нажмите «Сохранить калибровку».
3. Нажмите «Запустить распознавание». Служба создаст рядом с проектом `recognition-request.json`, физически выровняет каждый лист по сохранённому углу и поставит проект в фоновую очередь.
4. Если AI-исполнитель включён, каждый лист отправляется в OpenAI Responses API со Structured Outputs и `store=false`: отдельно верх листа с датами, обзор таблицы, пять увеличенных блоков по восемь строк и увеличенный блок рукописных итогов. Агент сверяет первую и последнюю строку каждого блока, читает даты забоя и разделки, тело и итоги. Числа затем нормализуются локально по правилам навыка `weight-register-scans`; сервер проверяет четыре угловые координаты, весовой итог первой строки для каждой занятой колонки и отклоняет результат с пропусками более 2% либо `Suspect` без конкретной визуальной причины. Необязательная вторая итоговая строка сохраняется отдельно и не подменяет сумму массы. Сравнение с автоматическими записями выполняется детерминированно за прочитанную дату забоя, которая обычно на сутки раньше даты разделки.
5. Если AI-исполнитель выключен, остаётся безопасный ручной маршрут: скачайте ZIP-пакет с `recognition-request.json` и всеми сканами из `source/`, распакуйте его, обработайте агентом с навыком `weight-register-scans` и импортируйте итоговый JSON кнопкой «Импортировать результат». Относительные `source_file` в JSON указывают на файлы внутри этого же пакета. Импорт принимает как современный массив `cells`, так и фактический legacy-формат WeightRegisterReviewApp с матрицей `data`; дата и полный набор соответствующих листов проверяются до сохранения.
6. Выберите ячейку для просмотра crop, автоматической пары и ручной коррекции. Двойной щелчок открывает диалог видеоархива.

Автоматическое распознавание по умолчанию выключено. Администратор проверяет модель на странице настроек (безопасное начальное значение — `gpt-5.6`), задаёт для `WeightRegisterReview:Recognition` параметр `Enabled=true` и создаёт системную переменную окружения с именем из `ApiKeyEnvironmentVariable` (по умолчанию `OPENAI_API_KEY`) для учётной записи Windows-службы. Сам ключ в `appsettings.json` не записывается; после изменения настроек или переменной службу нужно перезапустить. Формат запроса основан на официальной документации [Responses API](https://developers.openai.com/api/reference/resources/responses/methods/create), [image inputs](https://developers.openai.com/api/docs/guides/images-vision) и [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs).

До уточнения модели видеорегистратора адаптер выключен. После уточнения задайте `WeightRegisterReview:VideoArchive:Enabled=true`, `PreRollSeconds` и `UrlTemplate`. Поддерживаемые placeholders: `{weighingId}`, `{start}`, `{timestamp}`. Шаблон должен возвращать воспроизводимый браузером видеопоток или файл.

Для подключения конкретного регистратора нужно зафиксировать: производителя и полную модель, версию прошивки, номер камеры весов, локальный адрес, протокол архива (HTTP/HTTPS/RTSP или SDK производителя), способ авторизации, часовой пояс регистратора и формат возвращаемого потока. Отдельно требуется решить длительность фрагмента после момента взвешивания. Пароль в JSON не сохраняется: для него должен использоваться секрет службы или защищённая учётная запись регистратора.

Страница `/production-display` предназначена для отдельного монитора мини-ПК и раз в секунду показывает количество записей за текущий день и массу последнего сохранённого взвешивания.

### Общий и санитарный забой

Arduino отправляет `0x21` для общего и `0x22` для санитарного режима. В эскизе `IndicationController.ino` по умолчанию назначены:

- D7 — вход двухпозиционного переключателя (`HIGH` общий, `LOW` санитарный);
- D8 — лампа общего режима;
- D9 — лампа санитарного режима.

Перед подключением шкафа обязательно сверить эти пины с фактической схемой. При запуске и после потери COM-связи служба ждёт подтверждённое положение переключателя от Arduino, поэтому раннее взвешивание не получает молча режим «общий». Служба сохраняет режим по `WeighingId` в отдельном SQLite-файле `DatabaseSettings:WeighingModeDatabasePath`; запись веса и маркера считается одной операцией и при временной ошибке журнала повторяется через существующую очередь. Существующие записи без маркера считаются общими. Переключатель «Санитарный включён/исключён» на страницах мониторинга, статистики, сверки и экрана цеха фильтрует санитарные записи, сводку и экспорт. Если журнал режимов недоступен, режим исключения не показывает старые нефильтрованные значения как корректный результат.

До монтажа нужны фактическая схема клемм, рабочее напряжение ламп, тип и полярность входа релейных модулей, свободные Arduino-пины и подтверждение логики переключателя (`HIGH/LOW`). Прошивку нельзя переносить в шкаф только по фотографии SSR-модулей: назначение клемм и электрические уровни на ней не видны.

### Локальная проверка на ПК с .NET 8

Codex сборку и тесты не запускает. Разработчик выполняет локально:

```powershell
dotnet build Scalemon.sln -c Release
dotnet test Scalemon.CSTests/Scalemon.CSTests.csproj -c Release
```

Минимальные сценарии ручной проверки:

- загрузить два скана одной даты, откалибровать каждый и перезапустить службу — проект должен сохраниться;
- с тестовым API-ключом включить AI-исполнитель, распознать один откалиброванный лист и проверить переходы «в очереди → распознаётся → распознано»;
- при выключенном AI-исполнителе импортировать современный JSON schema v2 и один реальный JSON WeightRegisterReviewApp с `data`; проверить выбор автоматических данных по `slaughter_date`, все четыре цвета, crop и сохранение исправленного значения;
- переключить D7 и убедиться, что активна только одна из ламп D8/D9, затем сделать по одному взвешиванию в каждом режиме;
- выключить показ санитарных данных и проверить счётчик, таблицу и экспорт;
- открыть `/production-display` на отдельном мониторе и проверить обновление без перезагрузки;
- двойным щелчком открыть видеодиалог; до настройки регистратора он должен показать понятное сообщение без ошибки страницы.
